customer_tech

Layer: Silver Tech Materialization: Incremental Catalog: walmart.silver_tech Key: customer_id

Ingests customer data incrementally from bronze.customers. Automatically updates existing customer records and inserts new ones while maintaining a processed_at lineage marker.

Transformation Logic
{{
    config(
        materialized='incremental',
        unique_key = 'customer_id'
    )
}}

SELECT 
    *,
    current_timestamp() as processed_at
FROM 
    {{ source('walmart_db', 'customers') }}

{% if is_incremental() %}
    WHERE updated_timestamp > (SELECT COALESCE(MAX(updated_timestamp), '1900-01-01') FROM {{ this }})
{% endif %}

Jinja Meta-Programming Engine in obt.sql

Instead of hardcoding 140 lines of static JOINs, obt.sql defines a declarative configuration array and renders the multi-table query dynamically using Jinja loops.

📄 models/silver_b/obt.sql (Jinja Source) JINJA CONFIG
{% set configs = [ { "table": ref('orders_tech'), "alias": "o", "columns": """ o.order_id, o.customer_id, o.store_id, o.total_amount, current_timestamp() AS obt_processed_at """ }, { "table": ref('customer_tech'), "alias": "c", "columns": """ c.first_name AS customer_first_name, c.email AS customer_email, c.city AS customer_city """, "join_condition": "o.customer_id = c.customer_id" }, { "table": ref('order_items_tech'), "alias": "oi", "columns": """ oi.order_item_id, oi.product_id, oi.quantity, oi.unit_price, oi.line_amount """, "join_condition": "o.order_id = oi.order_id" }, { "table": ref('product_tech'), "alias": "p", "columns": """ p.product_name, p.category, p.brand, p.price """, "join_condition": "oi.product_id = p.product_id" }, { "table": ref('employee_tech'), "alias": "e", "columns": """ e.employee_id, e.first_name AS employee_first_name, e.job_title AS employee_job_title """, "join_condition": "o.store_id = e.store_id" }, { "table": ref('stores_tech'), "alias": "s", "columns": """ s.store_name, s.city AS store_city """, "join_condition": "o.store_id = s.store_id" } ] %} SELECT {% for config in configs %} {{ config['columns'] }} {% if not loop.last %}, {% endif %} {% endfor %} FROM {% for config in configs %} {% if loop.first %} {{ config['table'] }} AS {{ config['alias'] }} {% else %} LEFT JOIN {{ config['table'] }} AS {{ config['alias'] }} ON {{ config['join_condition'] }} {% endif %} {% endfor %}
⚡ target/compiled/walmart_db/models/silver_b/obt.sql COMPILED SQL
SELECT o.order_id, o.customer_id, o.store_id, o.total_amount, current_timestamp() AS obt_processed_at, c.first_name AS customer_first_name, c.email AS customer_email, c.city AS customer_city, oi.order_item_id, oi.product_id, oi.quantity, oi.unit_price, oi.line_amount, p.product_name, p.category, p.brand, p.price, e.employee_id, e.first_name AS employee_first_name, e.job_title AS employee_job_title, s.store_name, s.city AS store_city FROM `walmart`.`silver_tech`.`orders_tech` AS o LEFT JOIN `walmart`.`silver_tech`.`customer_tech` AS c ON o.customer_id = c.customer_id LEFT JOIN `walmart`.`silver_tech`.`order_items_tech` AS oi ON o.order_id = oi.order_id LEFT JOIN `walmart`.`silver_tech`.`product_tech` AS p ON oi.product_id = p.product_id LEFT JOIN `walmart`.`silver_tech`.`employee_tech` AS e ON o.store_id = e.store_id LEFT JOIN `walmart`.`silver_tech`.`stores_tech` AS s ON o.store_id = s.store_id;

See how dbt snapshots capture changes over time. Active records stay valid until 9999-12-31. When an update occurs, the previous record is retired and a new record takes over.

🔍 Point-in-Time Join Query Syntax (BI & Analytics):
SELECT f.order_id, f.total_amount, c.customer_city
FROM walmart.gold.fact_orders f
JOIN walmart.gold.dim_customer c
  ON f.customer_id = c.customer_id
 AND f.order_timestamp >= c.dbt_valid_from
 AND f.order_timestamp < c.dbt_valid_to;
All Layers Bronze Silver Tech Silver Business (OBT) Gold Marts
customers (Bronze) Source

Raw customer profile and contact coordinates.

  • customer_id (PK) BIGINT
  • first_name, last_name VARCHAR(100)
  • email, phone VARCHAR(255)
  • city, province, country VARCHAR(100)
  • created_timestamp, updated_timestamp TIMESTAMP
  • is_active CHAR(1)
products (Bronze) Source

Catalog of all Walmart inventory SKUs.

  • product_id (PK) BIGINT
  • product_name VARCHAR(255)
  • category, brand VARCHAR(100)
  • price NUMERIC(10,2)
  • created_timestamp, updated_timestamp TIMESTAMP
orders (Bronze) Source

Retail point of sale order header records.

  • order_id (PK) BIGINT
  • customer_id (FK) BIGINT
  • store_id (FK) BIGINT
  • payment_method, order_status VARCHAR(50)
  • total_amount NUMERIC(12,2)
order_items (Bronze) Source

Line-item purchases attached to an order.

  • order_item_id (PK) BIGINT
  • order_id (FK) BIGINT
  • product_id (FK) BIGINT
  • quantity INT
  • unit_price, line_amount NUMERIC(12,2)
obt (Silver Business) One Big Table

Consolidated wide table joining all 6 entity layers.

  • order_id, order_item_id BIGINT
  • customer_first_name, customer_email VARCHAR
  • product_name, category, price VARCHAR / NUMERIC
  • employee_first_name, job_title VARCHAR
  • store_name, store_city VARCHAR
  • obt_processed_at TIMESTAMP
fact_orders (Gold) Fact Table

Core transactional fact table at order item grain.

  • order_id, order_item_id BIGINT
  • product_id, store_id, employee_id, customer_id BIGINT
  • quantity INT
  • unit_price, line_amount, total_amount NUMERIC

Security & Zero-Credential Policy

The repository enforces strict multi-layer .gitignore barriers to protect your Databricks Personal Access Tokens (PATs) and internal database URIs.

🛡️ Protected by .gitignore:
  • walmart_db/profiles.yml (Databricks access tokens)
  • Walmart_dataset/.env (PostgreSQL URI & API keys)
  • walmart_db/.user.yml (User runtime state)
  • target/ & dbt_packages/ (Compilation artifacts)
  • **/logs/ & *.log (Execution traces)
✅ Recommended Safe Setup:

Use the provided sanitized template walmart_db/profiles.sample.yml and supply tokens via environment variables: 

export DATABRICKS_HOST="dbc-xxxx.cloud.databricks.com"
export DATABRICKS_HTTP_PATH="/sql/1.0/warehouses/xxxx"
export DATABRICKS_TOKEN="dapi_your_pat_here"
